Snippet 1: The 'var' Mystery

console.log(playerName);
var playerName = "Ansh";

Actual Output: undefined (Not an error!)

Explanation (Hoisting): In JavaScript, variable declarations (using var) are moved to the top of their scope before the code executes. However, the initialization (="Ansh") is left behind. So, JS knows the variable exists, but it hasn't been assigned a value yet when the console.log runs.

Snippet 2: Block Scope Clash

if (true) {
    var scoreVar = 90;
    let scoreLet = 100;
}
console.log(scoreVar);
console.log(scoreLet);

Actual Output: 90, followed by ReferenceError: scoreLet is not defined.

Explanation (Block Scope): Variables declared with var do not care about code blocks (like if or for loops); they leak out globally. Variables declared with let and const are strictly locked inside the { } block where they were created. They cannot be accessed from the outside.

Snippet 3: Time Travel Functions

triggerAlert();

function triggerAlert() {
    console.log("System Online!");
}

Actual Output: "System Online!" (It runs perfectly).

Explanation (Function Hoisting): Unlike variables, standard Function Declarations are fully hoisted to the top of the script, including their entire inner logic. This allows you to safely call a function in your code before you actually write the function definition.
